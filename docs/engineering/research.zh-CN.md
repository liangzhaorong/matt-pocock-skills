## 它做什么

`research` 通过阅读“拥有答案的那些来源”来回答一个问题，然后在仓库里留下一份带引用的 Markdown 文件。它只从**[一手来源（primary source）](https://www.aihero.dev/ai-coding-dictionary/primary-source)**工作：官方文档、源代码、规格、第一方 API。它把每条断言都回溯到拥有它的来源，所以只要 API 自己的文档够得着，它就不会转述某篇博客对那个 API 的说法。

它不在对话里回答你。输出是一份文件，写在仓库本来就放这类笔记的地方，每条断言带一个链接。你拿到的是一份可以回应、可以交给另一个智能体、也可以扔掉的文档，而不是一个[会话](https://www.aihero.dev/ai-coding-dictionary/session)结束就消失的答案。

## 何时该用它

输入 `/research`，或者当任务变成阅读型的跑腿活时，[智能体](https://www.aihero.dev/ai-coding-dictionary/agent)自动取用它。

当下一步是去工作目录*外面搞清楚某件事*（一个第三方 API 表现如何、一份规格说了什么、一个版本声明成不成立），而你不想为了读这些东西让自己的线程停摆时，找它。你需要什么决定用哪个技能：

| 你需要什么 | 用哪个 |
| --- | --- |
| 一个决策正等着的外部事实 | `research` |
| 一个*和你一起*通过访谈做出的决定 | [grilling](https://aihero.dev/skills-grilling) |
| 一个耐久的架构决定，写进 `GLOSSARY.md` 和 ADR | [grill-with-docs](https://aihero.dev/skills-grill-with-docs) |
| 搞清楚某个方案在你的代码库里行不行 | [prototype](https://aihero.dev/skills-prototype) |
| 一份大到装不进单次会话的计划 | [wayfinder](https://aihero.dev/skills-wayfinder) |

`research` 与 `grill-with-docs` 的分界线是**返回物的保质期**。调研产出短命的事实，比如这座库的鉴权机制截至本周做了什么。ADR 记录的是一个你会留下的决定。如果你产出的是一个决定而不是一个事实，那你是在[拷问](https://www.aihero.dev/ai-coding-dictionary/grilling)，不是在调研。

## 被委托出去的跑腿

阅读由一个**后台智能体**执行。你继续干活，它把每条断言追到一手来源，写一份 Markdown 文件，然后汇报回来。调研是你委托出去的跑腿，不是你外包出去的思考。你拿到一份可以对着拷问、规划或设计的文档，决定仍由你来做。

没有什么能阻止这个后台智能体再孵化一个自己的后台智能体。这是这个技能被记录得最充分的问题。

文件放哪由仓库决定，不是由技能决定。它遵循仓库已有的笔记约定。如果没有约定，它挑一个合理的位置并告诉你。每次运行写一个文件。

## 常见问题

**它孵化出了第二个调研智能体，这是有意的吗？**

不是。这是一个未关闭的 bug，[issue #530](https://github.com/mattpocock/skills/issues/530)。技能告诉调用者起一个后台智能体，却没有限制智能体类型。于是调用者起了一个 `general-purpose` 智能体，它有 `Agent` 工具、拿到同一份指示，然后照着再做一遍。一位报告者测到单个调研任务在三段重叠的运行里烧掉约 45 万 [token](https://www.aihero.dev/ai-coding-dictionary/token)，那个复制品在用户看不见的地方半小时后才跑完。这不是 Claude Code 独有：用户确认在 Codex 配 GPT-5.6-sol 里发生同样的嵌套。没有已发布的修复。有用户给自己装的那份打过一个补丁，加了一行“已经是[子智能体](https://www.aihero.dev/ai-coding-dictionary/subagent)的就自己干”。这有用，但只是一条指示，不是结构性的修复。调用这个技能之后，盯着你的后台任务列表，把复制品停掉。

相反方向的失败也会发生。如果你自己的全局指示禁止智能体再转委托工作，后台智能体会拒绝任务，技能就什么都不做，也不告诉你。

**这份文件该放哪，该提交吗？**

技能把文件放到仓库本来就放笔记的地方，再无别的意见。社区的看法基本已定：留 ADR，不留调研文件。一条关于这个问题的 Discord 讨论说得最清楚：“ADR 留。其他一切做完就归档或删除。否则它会变成工作的残渣，在你已经偏离规格/调研之后毒害未来对仓库的阅读。”一份调研文件记录的是写下当天为真的东西，所以一份过时的比没有更糟。总的说来，这些文件不属于 git，它们也没有标准归宿。人们改用 Obsidian、一个单独的知识仓库，或者 issue 跟踪器。

**什么算“高信任”的一手来源，谁说了算？**

[模型](https://www.aihero.dev/ai-coding-dictionary/model)说了算。技能点名了合格来源的*种类*（官方文档、源代码、规格、第一方 API），没有允许清单、没有领域门槛、也没有核验环节。这是技能最初被提出时最响的反对意见，至今没人公开回答过：“五个调研子智能体对着垃圾跑，只会更快地给你五个自信的错误答案。你对什么算高信任来源是怎么设卡的？”你唯一的保护是每条断言上的引用。随机跟两三条。如果它们落到的是对那个东西的转述而不是那个东西本身，这次运行就失败了。

**后面的会话会复用早前运行找到的东西吗？**

不会。没有什么会自动加载过去的调研文件。文件留在仓库里，直到某个人或某个技能指向它。这是对这份设计最早的也是最有力的一击：“价值在于那份 markdown 变成智能体日后重读的上下文，而不是抓取本身。一个写完即死的文件只是一次花哨的搜索。”已发布的技能没有解决它。实践中，只有当你亲自把文件喂进下一步时它才有用：把它附到规格上、把它引进拷问会话、让一张[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)指向它。

**为什么不直接叫智能体去读文档？**

可以，而且一句正好这么说的两行提示词就是这个技能取代的旧做法。技能给你两样提示词给不了的东西。它在后台跑，你会话的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)保持干净。而且一手来源约束和带引用的文件输出每次都一样，不随你提示词的措辞而变。与 [harness](https://www.aihero.dev/ai-coding-dictionary/harness) 自带的深度调研模式相比，差别在文件和一手来源规则，不在搜索。如果一个小问题上两行提示词就能拿到你要的东西，那就用两行提示词。

**它什么时候停止阅读？**

技能没有停止判据。这表现为两种看似相反、同根同源的抱怨：一类智能体钻得太深，另一类把一个主题扫得很宽，却漏掉了要紧的那一个细节。一位实践者这样说：“深度调研技能有时候有点太深。而叫智能体去调研，通常结果是漏掉关键细节。”范围得你来定。一个窄而可答的问题（一个 API、一个行为、一个版本声明）回来得远比“调研一下 X”好。

**`/wayfinder` 立了调研工单，要我自己去解决吗？**

不用，现在它替你发。自 v1.1 起未发布的改动里，一次制图会话会为每张调研工单起一个 `/research` 子智能体并行跑。每个子智能体把发现记录到一条用完即弃的 `research/<name>` 分支上，工单里留有指向它的[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)。调研工单是 wayfinder“每会话一工单”规则的唯一例外，因为它们是 [AFK（人不在键盘前）](https://www.aihero.dev/ai-coding-dictionary/afk)的：没有东西在等你。一个已知问题：日后删除那条分支会弄断工单里的上下文指针。

## 有这些表现就说明它在生效

- 你自己的会话在继续。如果你坐着看它读，委托就没有发生。
- 恰好出现一个新的后台任务。第二个名字几乎一样的是那个嵌套 bug。
- 恰好多出一份新的 Markdown 文件，落在仓库本来放笔记的目录里，智能体告诉你路径。
- 里面每条断言都带链接，随机跟两条，落到的都是官方文档、规格或源码文件本身，而不是谁写的转述。
- 只凭这份文件你就能做出刚才卡住的那个决定，不必自己回到来源。

## 它的位置

`research` 是一个随取随用的独立件。它喂养那些思考型技能，不是构建链条上的一环。是*你*把它的文件带进流程。[grilling](https://aihero.dev/skills-grilling) 和 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 在已经有事实时问出更锋利的问题，[to-spec](https://aihero.dev/skills-to-spec) 可以对着它做综合。[wayfinder](https://aihero.dev/skills-wayfinder) 是唯一直接调用它的技能：用 `/research` 子智能体解决地图上的每张调研工单。要看整张地图，见 [ask-matt](https://aihero.dev/skills-ask-matt)。
