## 它做什么

`retro` 回顾一次编程[会话](https://www.aihero.dev/ai-coding-dictionary/session)，并对智能体的**[环境](https://www.aihero.dev/ai-coding-dictionary/environment)**提出改进建议，让下一次运行更顺。它读的是会话本身的记录（默认是当前这次，也可以是你从会话日志里指给它的一次）。它找出智能体挣扎的时刻，给你一份候选修复的清单，最严重的排最前面。

它改的是环境，不是代码。比如智能体带出去的 bug、它花了二十次[工具调用](https://www.aihero.dev/ai-coding-dictionary/tool-call)才找到的文件、评审者漏掉的规则。`retro` 不会直接修复其中任何一个。它问的是仓库里的什么让这些事发生，并提议能防止它们下次再发生的检查、指针或规范。它同样只提议。在你选中某个候选之前，什么都不会变。

## 何时该用它

你通过输入 `/retro` 来调用它，智能体不会自己主动取用它。

在一场比应有的更艰难的会话结束时使用它。比如：智能体找某样东西找了太久、犯了一个本可被某个工具拦住的错误，或者需要它拿不到的信息。顺利的会话没什么可教的，发现来自艰难的会话。如果你想对这次会话产出的代码下判断，请改用 [code-review](https://aihero.dev/skills-code-review)。

## 发现落在哪里

每个候选都属于某一类，类别决定修复落到哪里：

| 会话中出了什么问题 | 用什么修 |
| --- | --- |
| 智能体花了很长时间找一个文件或事实 | 一条放在它本来就会读的文件里的**导航指针** |
| 它犯了一个本可被某个工具拦住的错误 | 一项**[自动化检查](https://www.aihero.dev/ai-coding-dictionary/automated-check)**：lint 规则、类型、测试、pre-commit hook、CI 任务 |
| 评审者漏掉了一个属于主观判断的错误 | 在 `CODING_STANDARDS.md` 里为评审智能体写一条规则 |
| `AGENTS.md` 或 `CLAUDE.md` 太大 | 把其中的引导（steering）内容挪出去，放进规范或检查 |
| 一次工具调用相对其回报太贵 | 精简该工具，或换掉它 |
| 某个引导文件里满是起不了任何作用的行 | 删掉这些**空操作（no-op）** |
| 智能体需要它够不着的信息 | 放宽它的访问面：把开发服务器的日志 tee 到一个文件、给某个服务只读权限 |

首要理念是：规范属于**评审者**，而不是实现者。实现智能体承受的上下文压力最大，因为它要探索、写代码、调试失败。评审智能体拿到的只是一个 diff，别无其他。所以新规则应该放到有空间去应用它的地方，也就是评审。它绝不进 [AGENTS.md](https://www.aihero.dev/ai-coding-dictionary/agents-md)，因为无论相关与否，它都会被加载进每一个会话的[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)。

在 `retro` 写下任何规则之前，它先给违规分类。**机械性**违规（被禁用的 API、某种 import 形态、文件位置规则）得到一个确定性的检查，因为检查会失败，而规范文件里的一句话不会。只有真正需要主观判断、任何 linter 都无法强制的违规，才写成散文。如果仓库完全没有护栏（没有 pre-commit hook，也没有跑 lint、typecheck 和测试的 CI 任务），`retro` 会把这一点本身作为一条发现报告出来。

## 常见问题

**它会自己动手写 lint 规则，还是等我点头？能把它接成每次会话后自动运行吗？**

它等。`retro` 只提议。在你选中某个候选之前什么都不会变，所以它不亲手编辑任何东西，也不自动安装任何 hook。这是有意为之。一位用户在“被自动 hook 拦住过好的改动”烧伤之后，要的正是这一点。判断什么值得变成一条永久检查需要判断力，所以这个技能保持[人在环中（human-in-the-loop）](https://www.aihero.dev/ai-coding-dictionary/human-in-the-loop)、保持用户调用。有些用户确实在每次实现运行之后都跑它。但顺利的会话没什么可教的，每次会话后都跑一遍，多半只会产出没人需要的规则。它没有 dry-run 模式。被提议的检查和其他代码一样是代码，先在仓库上试过，再让它去拦截合并。

**这不会让 lint 规则永远堆积下去吗？它会不会建议删掉某条？**

多少会，而这正是它最弱的地方。它能删散文：引导文件里的空操作（no-op），以及 `AGENTS.md` 或 `CLAUDE.md` 里本该放进规范或检查的引导内容。当这些文件很大时，它会把这些标记为待删除。它是拿它读到的那一次会话来评判它们的，所以请把每一条都当作删除测试的候选，而不是定论。它不会审计自己上个月提议过的 lint 规则、hook 或 CI 任务。它只看一次会话，所以它无法告诉你某条规则现在触发得太频繁，或它背后的 bug 已经消失。检查仍需你自己修剪。一条在好代码上不停触发的规则，就是该删掉它的信号。

**它会不会只是为了填满分类而编造泛泛的建议？**

这是对它最有力的一条批评。一位用户发现：“活儿一干完，AI 就容易忘掉会话中段的挣扎，编出泛泛建议来凑满 retro 的分类。”每个候选都必须来自会话自身的记录，所以建议是针对那次会话的。这既有代价也有好处：它很少编造无关的东西，但可能给这次会话碰巧关注的东西过高的权重。凡是追不到具体时刻的候选，直接丢弃。严重程度的排序也当作初稿看待，因为一个安静但昂贵的错误，可能排在一个显眼但廉价的错误后面。

**我的会话很长。现在就跑它，还是开个新的？**

默认它评审当前会话。那是最好的情形，因为那些挣扎还在上下文窗口里。如果会话已经走出了[聪明区（smart zone）](https://www.aihero.dev/ai-coding-dictionary/smart-zone)，就[清空（clear）](https://www.aihero.dev/ai-coding-dictionary/clearing)它，再开一个全新的 `/retro`，从会话日志里指向上一场会话。

**智能体老是犯同一个错误。我该往 `CLAUDE.md` 里加一行吗？**

通常不该，而 `retro` 在这件事上的抵制比对什么都坚决。`CLAUDE.md` 里的一行会被加载进每个会话，削弱文件里其他所有内容的分量，还会随代码变化而过时。如果错误是机械性的，修法是一个会失败的检查。如果它是主观判断问题，就写进评审者读的编码规范。`AGENTS.md` 和 `CLAUDE.md` 是放导航指针的地方，此外少有别的用途。出于同样的理由，`retro` 不是[记忆系统](https://www.aihero.dev/ai-coding-dictionary/memory-system)。它不存储发生过什么。它改变环境，让这个错误无法再次发生。

**我的配置里提到 `CODING_STANDARDS.md`，可我没有这个文件。它是哪来的？**

没有任何技能自带这个文件。第一次有会话找到一条给评审者的主观判断规则时，`retro` 会提议创建它。你接受之后，[code-review](https://aihero.dev/skills-code-review) 就会读它。你已经在维护的任何其他规范文档，比如 `CONTRIBUTING.md`，用法相同。

**它和 `improve-codebase-architecture` 有什么不同？**

输入不同。[improve-codebase-architecture](https://aihero.dev/skills-improve-codebase-architecture) 只需要代码，为代码寻找结构上的改进。`retro` 需要会话历史，改进的是智能体工作的环境，而不是代码。两个都用；谁也替代不了谁。

## 有这些表现就说明它在生效

- 每个候选都能回指会话中的一个具体时刻，而不是一条泛泛的最佳实践。
- 反复出现的错误变成会失败的检查，而你的 `AGENTS.md` 随时间变短，而不是变长。
- 如果某个检查本来已存在、只是没接上，发现就会是把它接上，而不是提议新建一个。
- 下一次做同类任务的会话能更快找到它需要的东西。

## 它的位置

`retro` 是主链的最后一步，在这里你回顾整条链走得如何：

```txt
grill-with-docs → to-spec → to-tickets → implement → code-review → retro
```

在一次值得学习的构建之后运行它：可以在同一场会话里，也可以指向那场会话的日志。顺利的构建之后可以跳过它。

- [code-review](https://aihero.dev/skills-code-review) 是 `retro` 最常调优的评审智能体。新的编码规范放进它 Standards 轴会去读的地方。
- [writing-for-agents](https://aihero.dev/skills-writing-for-agents) 为 `retro` 提议的每一个引导文件和技能定下写作风格，`retro` 在开始前会先加载它。

[ask-matt](https://aihero.dev/skills-ask-matt) 会在你不确定当下处境需要哪个技能时，在整个技能集之间为你路由。
