# 示例任务（Example tasks）

按所解决问题分组的任务。每个都点名启动其运行的触发器、一次运行做什么、以及它接下来触发什么。大多数工厂从其中一个起步，靠链上下一个成长。

## 未分诊的工单堆积

**Explore 任务**
- 触发器：一张工单被创建，或人给它打了标签。
- 做什么：把工单的论断对照代码库核查，能复现的就复现，把它归类（容易处理的、需要人的、不是 bug），并把发现留在工单上给实现者。它从不推送。
- 触发什么：为容易处理的触发一次实现者运行。其余情况以工单被标记为等待人类收尾。

## 就绪的工单等人实现

**Implementer 任务**
- 触发器：工单被人或 explore 运行标记为 ready。
- 做什么：构建该工单直到自动化检查通过，并打开一个 draft PR。
- 触发什么：一次自动评审运行。

## PR 等待评审

**Automated review 任务**
- 触发器：一个 PR 打开且尚无自动评审，或人给它打了标签。
- 做什么：对照代码库的标准和它来源的工单评审 diff。
- 触发什么：失败时触发一次返工运行。通过时它结束，PR 等待人工评审，之后由人合入。

## 失败的自动评审无人修

**Rework 任务**
- 触发器：一次自动评审运行判某 PR 失败。
- 做什么：只修自动评审点名的问题，并推送。
- 触发什么：一次自动评审运行。失败达到设定次数后，它以 PR 被标记为等待人类收尾。

## 规格大到一次运行装不下

**Decompose 任务**
- 触发器：一张规格工单被打了标签。
- 做什么：把规格拆成工单，每张记录它依赖哪些工单。
- 触发什么：一次实现者运行。

这里的实现者运行会挑下一张依赖全部关闭的工单，并再次触发自己，直到没有工单剩下。

## 迁移到更严的自动化检查

一条新 lint 规则（或更严的类型设置）被打开，但只有部分文件通过。规则先在通过的文件上强制执行，不通过的先坐在例外清单上。

**Ratchet 任务**
- 触发器：每日时钟。
- 做什么：从例外清单取下一个文件，修到通过更严的检查，并开一个 PR。
- 触发什么：一次自动评审运行。例外清单清空后，棘轮运行无物可取，迁移完成。

一天一个小 PR 让人工评审保持便宜，而检查只会越来越严。

## 用户报告的 bug 没人读

应用里的反馈按钮是一个工单来源：它把每份报告提成一张已经带好 explore 标签的工单。explore 运行做剩下的事。

## 生产问题发现得太晚

监视器（慢查询、错误率）是一个工单来源。它每个问题提一张工单，再看到同一问题时改为在开放工单上评论。修复合入后，问题若仍在，它重开该工单。

## 工厂自己的运行失败

**Fix 任务**
- 触发器：编排器报告一次失败的运行。
- 做什么：把失败日志提成工单，失败可修时以 PR 尝试修复。
- 触发什么：一次自动评审运行。fix 运行自身工作的失败不触发任何东西，所以修复永不链式。因为修复改的是工厂本身，它永远要人工评审。

## 代码库漂移

**Architecture 任务**
- 触发器：每夜时钟。
- 做什么：扫描近期变更寻找重构候选，并把它们合成一张工单提交。
- 触发什么：无。人挑一个候选并打标签，启动惯常的链。

## 同样的错误不断回来

**Retro 任务**
- 触发器：一个 PR 合入，限流为十个合入 PR 取一。
- 做什么：读该 PR、其工单、其自动评审与运行日志，以 PR 形式提议对工厂自身指令的修改。
- 触发什么：一次自动评审运行。
