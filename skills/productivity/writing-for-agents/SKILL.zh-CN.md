这是为代理消费的任何文档撰写方式的参考：一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份经由指针触达的文档。包装不同，写法相同：同样的杠杆让每一种都变得可预测，因为代理每次运行走的是同一个*过程*，而不是产出同一个输出。

当你写的文档是一个技能时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md) 了解 frontmatter、调用方式的选择和路由技能。

## 上下文指针（Context Pointers）

**上下文指针（context pointer）**是保存在代理上下文中的一条引用：它点名某份位于上下文之外的材料，并编码了触达它的条件。技能的 description 是一个指针；`AGENTS.md` 里点名某份文档的一行也是同一个东西。决定代理何时触达材料、以及触达得多可靠的，是指针的*措辞*，而不是它的目标。一个必达的目标配上一条措辞无力的指针，就是一个方差 bug（variance bug）：先把措辞磨锋利，只有在磨利失败时才把材料内联进来。

一个指针做两件事：说明材料是什么，并列出应触发触达的**分支（branch）**（一个分支是文档处理的一种独立情形，因此不同的运行会沿不同路径穿过文档）。常驻加载的指针，每个词在每一轮都要付费，所以它比正文更配得上狠修剪：

- **把领头词（leading word）放在最前面**：指针正是它发挥触发作用的地方。
- **每个分支只留一个触发词。** 给同一个分支改名的同义词，是一个分支写了两遍；把它们合并，只保留真正不同的分支。
- **删掉正文已自带的身份性描述。**

## 两种负载（The Two Loads）

你添加的每一份文档和每一个指针，花的都是两份预算之一：

- **上下文负载（context load）**是常驻材料对代理窗口收取的成本：`AGENTS.md` 里的一行、一条技能 description、任何每轮都待在上下文里的东西，无论是否触发，都在消耗 token 和注意力。
- **认知负载（cognitive load）**是加在人身上的成本：存在哪些文档、各在什么时候去用。人就是索引。这不是该最小化的成本：它是人类能动性的代价；在人类判断要紧的地方花它，在不要紧的地方移除它。

只能经由指针触达的材料，以指针自身那一行为代价，逃掉了上下文负载；完全没有指针的材料，则全部骑在认知负载上。

## 信息层级（Information Hierarchy）

文档由两类内容构成：**步骤（steps）**（代理按序执行的动作）和**参考资料（reference）**（定义、规则、按需查阅的事实）。两者可以自由混合：全是步骤（一份操作指南）、全是参考资料（一套评审规则、本技能），或两者兼有。核心决策是每一块内容坐在**信息层级（information hierarchy）**的哪一级上：这是一架梯子，按代理需要该材料的迫切程度排序：

1. **文件内步骤（in-file step）**是主层级：代理按顺序要做的事。
2. **文件内参考资料（in-file reference）**按需查阅。它们常常是合法的平级集合（一套评审的所有规则坐在同一级上），这是一种好安排，不是坏味道。
3. **披露式参考资料（disclosed reference）**被推到单独的文件里，经由一个上下文指针触达，只在指针触发时加载。其范围从同文件夹的兄弟文件，一直到可放在任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶层就会膨胀；推得太多，你就藏起了代理真正需要的材料。这股张力就是整个决策。

**渐进式披露（progressive disclosure）**就是沿梯子向下移动（移出主文件、放到一个指针后面），让顶层保持可读。它首先不是 token 优化：它是信息层级得以被保护的方式。分支是最干净的披露检验：每个分支都需要的就内联，只有部分分支会到达的就推到指针后面。当文档含有步骤时，本该披露的文件内参考资料会把它们埋起来，让"是否注意到它们"变成掷硬币：这是一根方差杠杆（variance lever），而不只是可读性杠杆。

**就近聚合（co-location）**是文件之内的同伴：梯子决定一块内容坐*多深*，就近聚合决定它到位之后*谁坐在它旁边*。把一个概念的定义、规则和注意事项放在同一个标题下，而不是四处散落，这样读到一部分就顺带带出它的邻居。检验标准：文档读起来应该像专门为代理写的文档。聚拢的材料读起来是这样；散落的材料不是。（它与重复不同：重复是把同一个意思写在两个地方；散落是把同一个意思打碎在许多地方。）

**蔓生（sprawl）**是这里的失效模式：一份文档单纯地太长了，哪怕每一行都有效且独一无二。注意力被冗余摊薄，每多一行就多一行需要保持相关。解药是那架梯子：把参考资料披露到指针后面，按分支或序列拆分，让每条路径只带它需要的东西。

## 步骤与完成标准

每个步骤都终止于一个**完成标准（completion criterion）**：告诉代理工作已完成的条件。两个性质使它成为杠杆：

- **清晰（clarity）**：代理能分清"完成"和"未完成"吗？一个模糊的边界（"达成了理解"）会招来**过早完成（premature completion）**：在真正做完之前就结束步骤，注意力滑向*完成的状态*。前方还看得见的步骤（**完成后步骤**，post-completion steps）提供拉力；完成标准的清晰度就是阻力。按顺序设防：**先把边界磨利**（局部且便宜）；只有当它无法再磨利、*且*你确实观察到抢跑时，才靠拆分序列把后面的步骤藏起来。藏只在真正的上下文边界之外才有效（一次交接或一次子代理派发；内联调用会把后面的步骤留在上下文里，什么也清不掉）。
- **要求量（demand）**：它要求多少。"每个改动的模型都已交代"强制出彻底的工作，而"产出一份变更清单"不会。要求量驱动**跑腿活（legwork）**（代理在工作内部做的挖掘，潜伏在措辞里，而不是写成单独的步骤），而且它不限于步骤："每条规则都已应用"约束一段平铺参考资料，就像"每步都已做完"约束一个序列；纯参考文档正是这样仍带着一条穷尽性底线。

最强的标准既可检验又穷尽。

## 何时拆分

把一份文档拆成两份，花的是两种负载之一，所以只有当这一刀值回成本时才拆：

- **按序列**：当完成后步骤诱使代理抢跑眼前这一步时，拆开这段步骤。让它们离开视线，会驱动代理在当前任务上做更多跑腿活。当心反方向：合并序列会让每一步的后续步骤暴露在紧随其后的内容面前，招来过早完成。
- **按调用方式**，技能专属：见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 领头词（Leading Words）

**领头词（leading word）**是一个早已活在模型预训练中的紧凑概念，代理在运行文档时用它来思考（*lesson*、*fog of war*、*tracer bullets*）。它作为 token 被重复，绝不作为句子；通过征用模型已有的先验，它积累出一份分布式定义，用最少的 token 锚定一整片行为区域。自造词也可以，只要你定义得清楚，但一个编造的词征用不到先验：预训练词免费给你的东西，你要用定义 token 来付账；先去找现成的词。

它锚定两次。在正文里，锚定*执行*：这个词每次出现，代理都会伸手取用同一个行为；而在平铺参考资料中，它把注意力聚焦到该寻找的一类东西上。在指针里，锚定*调用*：当同一个词同时活在你的提示词、你的文档和你的代码库里，代理会把这门共享语言与材料关联起来，更可靠地触达它。

主动猎取用领头词重构的机会。在三个位置各自铺陈开的同一组三连词、一条花掉一整句话去比划某个想法的指针，每一段都在乞求坍缩成一个 token：

- "fast, deterministic, low-overhead"（快、确定性、低开销）→ *tight*（一个 *tight* 循环）。
- "a loop you believe in"（一个你信得过的循环）→ *red*，把一道模糊的闸门变成一个二值的可观察状态（这个循环在该 bug 上变 *red*，或者没变）。

你赢两次：token 更少了，代理挂靠思考的钩子更利了。假定每份文档都载着一些能被领头词退役的复述。去找出它们。

**否定式（negation）**是这根杠杆旁的失效模式：靠禁止来导航，会把被禁的行为拖进上下文，让它*更*可得，而不是更不可得。*别想大象*，结果满脑子都是大象；否定词是个弱修饰语，会被强激活的概念碾过去，于是这道禁令读起来一半像在做那件事的指令。用**肯定式**写提示：直接陈述目标行为（"写一行式注释"），让被禁的那个根本不被说出。禁令只有在无法用肯定式表述的硬护栏场合才配存在；即便那时，也要配上肯定式目标，让注意力落在该做什么上。

## 修剪（Pruning）

- 把每个意思保存在**唯一的真相来源（single source of truth）**里：一个权威位置，让改行为变成一处编辑。**重复（duplication）**（同一个意思出现在多个地方）耗费维护和 token，还把一个意思在梯子上的显著度抬高到超出它的真实级别。（这是领头词的意外反面：领头词有意重复的是 token，绝不是意思。）
- **环境**也是真相来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），复述环境的文档是一份**缓存（cache）**：一次查询的副本，只有当查询本身很贵时才值回它的负载。缓存代理看一眼找不到的东西：没写下来的约定、某个选择背后的原因、任何配置都不会坦白的坑。把一查一个文件、一查一条命令的查询留给环境，在那里它们不会过期。
- 逐行检查**相关性（relevance）**：它仍然关系到文档所做的事吗？一行可以因为从未与任务相关（纯粹的铺陈，或一个本该披露的分支）而失去相关性，也可以随着它所描述的行为或世界的变化而过期。文档越短越容易保持相关。没有修剪纪律，默认命运就是**沉积层（sediment）**：因为添加显得安全、删除显得危险而不断沉降的过期层，直到你必须钻透它们才能找到还活着的东西。
- 逐句猎取**空转句（no-op）**：模型默认就会遵守的指令，付出负载却什么也没说。检验（相对默认行为，它改变行为吗？）是相对于模型的，不是相对于读者的：两个对空转句意见不一的人，争的其实是默认行为；靠运行文档来裁决，而不是靠辩论。一句话不过关时，删掉整句，而不是从里面修剪字词。这个检验也给领头词打分：弱到赢不过默认行为的词（代理已经挺细致时说 *be thorough*）就是空转句，修法是换更强的词（*relentless*），而不是换别的技巧。
