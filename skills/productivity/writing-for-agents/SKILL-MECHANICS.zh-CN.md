# 技能机制（Skill mechanics）

[`writing-for-agents`](SKILL.md) 的技能专属分支：当文档是一个技能时，什么会变（frontmatter、调用方式的选择，以及路由技能）。关于写作的其他一切，都在 `SKILL.md` 的通用参考里。

## 调用方式（Invocation）

两个选择，权衡的是两种负载：

- **模型调用（model-invoked）**技能保留 `description`，因此代理可以自主触发它，其他技能也能触达它。你仍然可以手动输入它的名字：模型调用永远*包含*用户可达；description 只会增加代理的可发现性，绝不会移除人的。description 是技能的顶层上下文指针，被迫始终常驻加载：用永久的上下文负载换取可发现性。一个内容全是参考资料的模型调用技能，还可以作为共享参考资料的家：其他技能可以调用它，于是多个技能都需要的参考资料就活在一个地方。机制：省略 `disable-model-invocation`，写一条面向模型的 description，携带触发分支（`SKILL.md` 中的指针写作规则完全适用）。
- **用户调用（user-invoked）**技能把 description 从代理的可达范围中剥掉：只有手动输入其名字的人才能调用它，其他任何技能都不能。上下文负载为零，但要花认知负载：你就是那个必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 变为面向人类：一行摘要，剥掉触发词列表。

只有当代理必须自行触达该技能，或另一个技能必须触达它时，才选模型调用。如果它永远只会被手动触发，就做成用户调用，不付任何上下文负载。

两个用户调用技能都需要的共享参考资料，哪一边都放不下：没有 description，谁也触发不了谁。把它推到技能系统之外的一个普通文件里：任何技能都能指向的外部参考。

## 按调用方式拆分（Splitting by invocation）

拆分中的调用切分（序列切分见 `SKILL.md`）：当你有一个足够独立、应当独立触发它的领头词（一个你确实会在自己的提示词里用到的触发词），或另一个技能必须触达它时，才拆出一个模型调用技能。你要为新常驻的 description 支付上下文负载，所以这次独立触达必须值回票价。

## 路由技能（Router skills）

当用户调用技能多到超出你能记住的数量，这堆高的认知负载由一个**路由技能（router skill）**来治：一个用户调用技能，点名其他技能以及各在何时使用，于是人只需记住一个技能，而不是许多个。它只能提示，永远不能触发它们：用户调用技能没有 description，除了人，谁也触达不了它们。
