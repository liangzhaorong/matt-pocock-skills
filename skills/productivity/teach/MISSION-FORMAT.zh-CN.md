# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习这个主题的*原因*。每一项教学决策（接下来教什么、呈现哪些资源、设计哪些练习）都应能追溯回这份文档。

## 模板

```md
# 使命：{主题}

## 为什么
{1-3 句话。用户追逐的具体真实世界目标。掌握这项技能后，他们的生活或工作
会发生什么变化？避免"为了理解 X"这类抽象表述；追问到底层的实际产出。}

## 成功是什么样子
- {一件用户将能做到的具体、可观察的事}
- {另一件具体的事}
- {……}

## 约束
- {时间、预算、既有承诺、学习偏好，任何限定做法的因素}

## 范围外
- {用户明确表示现在不想追逐的相邻主题，以保护最近发展区}
```

## 规则

- **一个工作区一个使命。** 如果用户想学两件不相关的事，那就是两个工作区。
- **具体胜过抽象。** "十月前跑完半程马拉松"胜过"变得更健康"。"给团队交付一个 Rust CLI"胜过"学会 Rust"。
- **对含糊其辞要追问。** 如果用户说不清为什么，先访谈他们再动笔。糟糕的使命比没有使命更糟。
- **现实变了就修订。** 使命会变。当用户的目标移动时，更新此文件：不要让一份过期的使命继续主导未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是罗盘，而变成了计划。
